# Research guidance

논문 조사·읽기·재현, 학습·평가, 연구 주제 선정과 원고 검토에 적용한다. 수행하는 작업에 해당하는 section을 사용한다.

## Source of truth

- 논문 note, reading evidence, implementation attempt, review와 recall record의 canonical owner를 명시한다.
- PDF, credential, private review export와 개인 원문은 public repository에 올리지 않는다.
- public output은 명시적으로 선택한 field만 schema validation 후 별도 feed로 publish한다.
- slug, identifier, provenance와 visibility를 안정적으로 유지한다.

## Workflow

1. 수집하거나 queue에 등록한다.
2. 읽기 pass와 질문을 기록한다.
3. 주장과 근거, 출처, 읽은 시점을 분리해 남긴다.
4. 구현 또는 재현 결과를 논문 record와 연결한다.
5. review/recall로 이해도를 검증한다.
6. 공개 가능한 field만 의도적으로 publish한다.

## Safety and evidence

- 원본 삭제·덮어쓰기나 공개 범위 변경처럼 실제 위험이 있는 작업에는 대상과 영향을 먼저 검증한다. 이미 승인된 일상 작업에 일괄적인 dry-run, `--apply`, 반복 확인을 요구하지 않는다.
- seed, demo, 빈 record, generated fixture를 실제 연구 활동으로 집계하지 않는다.
- 관측값, 추론, 의견을 구분한다.
- 실패와 미완료 상태를 숨기지 않는다.
- 자동 생성 report는 artifact이며 장기 지침 문서가 아니다.

## Reading-to-publication workflow

- 일일 읽기 계획은 논문을 선택하는 개인 작업 상태이며 읽기·이해·검토 완료의 근거가 아니다. 목표 수와 실제 활동을 분리하고 같은 논문의 여러 세션을 여러 편으로 집계하지 않는다. 날짜 기준은 사용자 현지 날짜를 사용하며 자정·시간대 변경을 검증한다.
- 논문에서 개인 리뷰 초안을 만들 때 기존 연결된 초안을 먼저 이어 쓸 수 있게 한다. 초록, 개인 메모, 세션 기록과 첨부를 자동으로 공개용 본문에 복사하지 않는다. 실제 작성한 메모를 옮겨야 하면 범위를 직접 선택하고 정확한 생성 본문을 미리 확인한다.
- 읽기 timer와 개인 작업 상태는 workspace와 stable record identity에 귀속한다. 경로만 같은 다른 record나 repository에 이전 상태를 자동 연결하지 않는다. 이전 형식의 상태는 대상과 내용을 검토한 뒤 명시적으로 복원하고, 이미 저장한 활동을 다시 기록하거나 더 새로운 메모를 정리 과정에서 버리지 않는다.
- 리뷰를 이어 쓸 때 언어와 원문 연결을 함께 확인한다. 기존 리뷰가 있다는 이유로 오늘의 읽기 단계를 건너뛰거나 공개 완료로 표시하지 않는다. 새 초안의 기본 언어는 선택한 원문을 따르되 사용자가 바꾼 언어와 제목은 미리보기 갱신 중 보존한다.
- 같은 논문의 새 리뷰는 원문 연결을 유지하면서 독립적인 문서 ID를 가진다. 이전 리뷰의 삭제·보관을 ID 재사용의 근거로 삼지 않는다. 생성→발행→삭제→새 리뷰 작성까지 검증해 이전 발행·복구 기록이 새 원고를 막거나 덮지 않게 한다.
- 원문의 주장·실험 근거와 작성자의 해석·평가·불확실성을 구분한다. 공개용 개인 리뷰에는 원문 출처와 해당 언어의 간결한 개인 의견 안내를 포함한다. 안내를 학술 검증이나 법적 면책의 보장처럼 표현하지 않는다.
- 발행 준비 점검은 출처·본문·공개 설정의 누락을 알려 주는 도구다. 템플릿이 존재하거나 글자 수를 채웠다는 이유로 이해도·정확성·동료 검토 완료를 선언하지 않는다. 준비, 저장, 공개 미리보기와 실제 배포는 구분하고 마지막 공개 여부는 검증된 배포 결과로 판단한다.

## Training execution and explanation

- 개인 연구 작업 환경을 이전할 때는 이미지 하나·컨테이너 하나 안에 모델별 conda/venv를 따로 유지하는 구성을 기본으로 한다. 버전 분리 요구를 이미지·컨테이너 다중화 요청으로 확대하지 않으며, 다른 구성이 필요하면 실제 실행 요구와 연결해 설명한다.
- 기존 연구 컨테이너와 같은 환경을 요청받으면 기준 생성 스크립트·실제 상태·base image의 전체 차이를 먼저 목록화한다. 사용자가 언급한 도구만 확인하지 않고 전체 설치 도구와 사용자 설정의 이관 여부를 정한다. 패키지 외에도 private/shared 마운트, 절대 경로·링크, 사용자·그룹 이름과 쓰기 권한, 로그인 셸·기본 환경, 데이터·checkpoint·실험 계약을 보존한다. import·GPU 연산 확인만으로 준비 완료를 선언하지 않고 실제 설정의 모델과 데이터 로더 실행을 확인하며, 원본부터 실패하는 조건과 이전 오류를 구분한다.
- 학습 실행은 가장 최근의 사용자 요청을 따른다. 명령만 요청하면 직접 실행하지 않고, 이후 실행을 요청하면 이전의 명령 제공 선호를 이유로 멈추지 않는다. tmux pane별 명령은 각 pane에 붙여 넣을 완결된 형태로 준다. 요청 없이 계속 상태를 조회·대기하지 않는다.
- 실행 준비에는 필요한 짧은 검증만 포함한다. 긴 학습의 완료를 기다리며 대화를 점유하지 않고, 사용자가 결과 확인이나 모니터링을 요청했을 때 해당 범위만 확인한다.
- 전체 데이터 학습·평가를 요청하면 소규모 시험이나 일부 표본으로 대신하지 않는다. 전체 train/test 범위와 제외 기준을 명시하고, 짧은 시험은 본 실행 전 확인에만 사용한다. 전체 실행이 어려우면 축소 실행을 완료 결과로 제시하지 말고 이유와 미완료 범위를 알린다.
- 사용자가 열어 둔 tmux의 살아 있는 pane을 보존한다. 지정한 pane 안에서 작업을 실행하고 완료 뒤에도 shell이 남도록 한다. pane 정리를 요청하면 종료가 확인된 pane만 정리하며, 살아 있는 pane을 닫거나 교체하지 않는다.
- 모델 이름만 적지 않는다. 가져온 모델의 출처와 checkpoint, 공개된 기존 학습 이력, 이번 실험에서 추가로 학습하는 데이터와 목표를 구분해 설명한다. 공개되지 않은 이력은 추정하지 않는다.
- `학습 전`은 무엇을 추가로 학습하기 전인지 명시한다. 비교 조건은 처음 등장할 때 입력 데이터, 생성 방법과 학습 여부를 짧게 정의하고, 뜻을 설명하지 않은 별칭만으로 결과를 제시하지 않는다.
- 실험을 확대하거나 수정할 때 사용자가 요청한 비교 조건을 다른 방법으로 조용히 대체하지 않는다. 방법·데이터 범위·평가 방식이 바뀌면 별도 실험으로 이름과 대응 관계를 기록하고, 원래 요청에서 아직 실행하지 않은 범위를 명시한다. 같은 별칭을 다른 뜻으로 재사용할 때도 차이를 먼저 설명한다.
- 결과에는 비율과 함께 맞힌 수·전체 수를 적고, 문항 수·교란 입력 수·학습 반복으로 처리한 입력 수를 구분한다. 방법을 예시로 설명할 때는 실제 학습 입력·추가 문장·학습 목표 정답·평가 입력·모델 출력을 순서대로 연결한다. 실제 기록과 가상 예시는 각각 표시한다.
- 발표·공유용 결과 보고서는 핵심 결론과 실제 입력·출력 사례로 시작하고, 연구 질문→비교 이유→결과→판단을 연결한다. 표마다 무엇과 비교해 어떤 주장을 뒷받침하는지 설명한다. 전체 실행별 수치는 상세 기록에 보존하고, 본문을 실행 순서나 수치 목록으로 대체하지 않는다.
- 기존 발표 자료를 참고해 논문 발표를 만들 때는 지정된 자료의 전체 슬라이드를 먼저 검토해 구성, 서체, 글과 그림의 비중, 수식 설명 방식을 파악한다. 로봇 동작과 Physical AI 개념에는 공식 자료의 실제 예시 사진과 연속 동작 프레임을 충분히 배치해 수식·구조·결과와 연결한다. 발표 시간과 청중의 배경에 맞춰 본문을 구성하고, 청중에게 필요한 사전 개념과 질의응답용 상세 자료를 구분한다.
- 논문 발표에서 분야를 처음 접하는 청중에게는 필요한 사전 개념과 실제 예시를 먼저 설명한다. 표지의 낭독 원고는 쉬운 주제 소개로 시작하고, 아직 정의하지 않은 연구 용어로 질문이나 기여를 제시하지 않는다. 사전지식 뒤에 실용 문제, 대표 선행연구가 이미 달성한 것과 남은 한계, 논문의 핵심 기여와 실제 해결 범위를 연결한 뒤 방법을 설명한다. 각 실험·ablation을 해당 기여의 근거로 연결하고, 중요성과 아직 해결하지 못한 범위를 구분한다.
- 영문 발표의 Presenter notes는 영어 원고를 먼저 쓰고 그 아래 한국어 번역을 배치하며, 두 언어 모두 문장마다 줄을 바꾼다. 노트에는 발표에 사용할 설명만 두고 출처는 별도 References 슬라이드에 모은다. 사용자가 수정한 최신 첨부본이 있으면 이를 기준으로 추가한 설명과 의도를 보존한다.
- 원고를 줄일 때 슬라이드마다 독립적인 설명을 나열하지 않는다. 앞 슬라이드의 문제·관찰·결과가 다음 설명이나 실험을 필요로 하는 이유를 연결하고, 반복되는 내용을 합쳐 분량을 줄인다. 기존 방법의 구체적인 문제, 연구의 중요성, 제안 방법이 이를 해결하는 원리는 본문에 유지한다. 실제 단어 수와 여유 있는 발화 속도, 그림을 짚고 청중이 이해할 시간을 함께 계산한다. 빠르게 읽게 만들지 말고 핵심 설명을 남기면서 부가 비교·수식·실험은 본문에서 줄이거나 backup으로 옮긴다.
- 논문 발표의 기본 성능 비교는 편집 가능한 표로 제시한다. 데이터 효율이나 모델 크기에 따른 추세 그래프는 해당 질문을 설명할 때 사용하고, 기본 성능표를 대신하지 않는다.

## Research topic recommendations

- 대학원 수업·연구 프로젝트에서 "재미있고 흥미롭고 기발한 주제"는 학술적으로 의미 있는 질문과 탐구의 흥미로 해석한다. 사용자가 요청하지 않은 게임화·오락형 시연을 주제 선정의 기본 방향으로 삼지 않는다.
- 연구자·연구원·교수에게 설명할 문제의 중요성, 기존 연구와의 관계, 검증 가능한 질문, 데이터와 평가 방법을 먼저 제시한다. 발표 연출이나 눈에 띄는 이름으로 학술적 기여를 대신하지 않는다.
- 시간·계산 자원 제약은 연구 범위와 구현 부담을 줄이는 조건이다. 대조 실험, 평가의 타당성, 결과 해석의 엄밀성을 생략하는 근거로 사용하지 않는다.

## Research redesign

- 누적 피드백으로 실험을 다시 설계할 때 이전 결과와 요구사항의 대응표를 먼저 만든다. 사용자 예시는 검증하려는 원리와 적용 범위로 해석하고, 예시의 문구나 개수에 실험을 한정하지 않는다. 실제로 미실행한 요구는 완료된 다른 비교로 대체하지 않는다.
- 설계 전에 사용자가 지적할 핵심 반론, 필요한 대조, 발견 가능성이 낮아 제외할 실험을 명시한다. 작업 중에는 확인한 근거와 채택·수정·폐기의 이유를 전달한다. 추가 실험 수나 새로운 명칭으로 연구 기여를 대신하지 않는다.
- 사용자가 독립 검토 loop를 요청하면 각 loop의 검토자를 새로운 문맥으로 시작시킨다. 요구사항·근거·구체적 설계와 주장 범위를 전달하고, 판정과 수정 내역을 남긴다. 요청된 OK를 받은 뒤 실행하며, 설계 검토의 OK와 실제 성능·신규성 입증을 구분한다.

## Theory-to-code learning

- 연구 방법을 code level로 학습하는 실습에서는 핵심 연산의 줄·구획마다 한글 주석으로 수식의 변수, tensor shape, 입력·출력과 코드 흐름을 연결한다.
- 강화학습을 기초부터 배우는 실습은 state, observation, action, policy, environment, reward와 종료 조건을 실제 한 step의 입력·처리·출력으로 모두 연결한다. 완성된 환경 안에 숨겨진 관측·행동 변환·보상·reset 로직은 직접 읽고 수정할 수 있게 제공하고, 물리 엔진이 계산하는 범위를 구분한다.
- 복잡한 실제 repository를 단순화할 때는 생략·대체한 부분을 명시하고, 원래 구현의 함수와 실습 코드의 대응 관계를 남긴다.
- 학습과 추론을 분리해 실행 가능한 작은 예제를 제공하고, 중간 tensor와 실제 실행 결과의 시각화를 함께 보여 준다. 설명용 경로와 학습된 모델의 생성 결과를 구분한다.

- Schema·visibility contract가 있는 경우 해당 문서를 유지한다. 같은 역할의 파일을 중복 생성하지 않는다.

## 원고 검토

- Live Overleaf project는 읽기 전용으로 검토한다. Source 입력·교체·삭제와 recompile을 수행하지 않고, 확인한 file·section·line과 사용자가 적용할 replacement 또는 patch를 제공한다.
